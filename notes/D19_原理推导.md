## 1. MinHash 为什么能估 Jaccard（完整推导）

设 A、B 是两个文档的词集合。哈希函数 h 均匀随机选一个元素。

P[h(A) == h(B)]

拆成两种情况：
- h 选中的元素在 A∩B 里 → 两边最小值必然相同
- h 选中的元素只在 A 或只在 B → 两边最小值大概率不同（除非更小的元素也在交集里，会被递归包含进交集情形）

严格地说：P[min(A) == min(B)] = |A∩B| / |A∪B| = J(A,B)。

用 k 个独立哈希函数，签名 sig(A) = (h1(A),...,hk(A))。

由期望的线性性：

    E[ (1/k) · Σ 1{sig(A)[i]==sig(B)[i]} ] = J(A,B)

即 **k 个位置上相等的比例，是 Jaccard 的无偏估计**。

标准误（比例的抽样方差）：

    SE ≈ sqrt( J(1-J) / k )

k=112、J=0.5 时 SE ≈ sqrt(0.25/112) ≈ 0.047，即 ±0.05。

## 2. LSH 分桶的概率推导

签名长 k = b · r，切成 b 个 band，每 band r 个 hash。

一个 band 内 r 个 hash 全部相等的概率（真实 Jaccard = s）：

    s^r

（因为每个位置独立，相等的概率是 s，r 个都相等是 s^r）

至少一个 band 全部相等（成为候选）的概率：

    1 - (1 - s^r)^b

这是标准 S 曲线：s 低时接近 0（相似的不进候选），s 高时接近 1（相似的必进候选）。

**拐点（阈值）**：令 P = 0.5 近似求解曲线中点，得

    s_threshold ≈ (1/b)^(1/r)

代入：

| b | r | 阈值 |
|---|---|---|
| 14 | 8 | 0.719 |
| 45 | 20 | 0.827 |

---

## 3. b / r 怎么选（工程含义）

- **r 越大**：要求 band 内全中的门槛更高 → 曲线更陡 → 阈值高 → 精确率高、召回低
- **b 越大**：band 更多 → 曲线更宽 → 阈值低 → 召回高、候选对多（后续精确比对成本上升）

**生产做法**：FineWeb 选 b=14, r=8（阈值 0.719），RefinedWeb 选 b=45, r=20（阈值 0.827）。
区别在于 RefinedWeb 的语料规模更大、对精确率要求更高，所以用更严的阈值换取更少的误删。

## 4. datatrove 默认参数（源码实证）

文件：`src/datatrove/pipeline/dedup/minhash.py`

```python
n_grams: int = 5
num_buckets: int = 14        # = b
hashes_per_bucket: int = 8   # = r
num_perms: int = 112         # = k，签名长度
```

**注意命名对应关系**：
- `num_buckets` = b = band 数 = 14
- `hashes_per_bucket` = r = 每 band hash 数 = 8
- `num_perms` = k = 总签名长度 = 112（= b × r）

## 5. 踩坑记录

### 5.1 网络

- huggingface.co、github.com 网页版、en.wikipedia.org 在这台机器超时
- HF 内容用 `https://hf-mirror.com/...`
- GitHub 源码用 `https://raw.githubusercontent.com/<owner>/<repo>/main/<path>`
- 仓库文件树用 `https://api.github.com/repos/<owner>/<repo>/git/trees/main?recursive=1`

### 5.2 zhwiki dump 是 multistream

`zhwiki-latest-pages-articles-multistream.xml.bz2` 里是**多个独立 bz2 流拼接**，
可以：
1. 只下载前 N MB（`urllib` 的 `r.read(max_bytes)` 或 HTTP Range）
2. 循环 `BZ2Decompressor` 解压，用 `unused_data` 拿到下一个流的起点
3. 从解压后的 XML 里正则抽 `<page>` / `<title>` / `<text>`

实测：25MB 压缩包 → 200 篇文档 → 清洗后 182 篇 / 50 万字符。

### 5.3 中文 wikitext 必须清洗

不清理的话正文里全是 `{{模板}}`、`[[链接|文字]]`、`<ref>` 标记，
会让 MinHash 算的是「模板噪声」的相似度而不是正文。
清洗顺序：去模板 → 去 ref → 去 wiki 链接 → 去粗斜体标记 → 截断长度。
